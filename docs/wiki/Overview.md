# 项目概览

> 三个问题：Fissue 是什么、怎么跑、现在靠谱到什么程度。细节分别见[架构设计](Architecture.md)、
> [快速开始](Getting-Started.md)、[基准与可信度](Benchmark.md)。

## 1. 它解决什么问题

维护仓库最痛的不是写代码，而是面对一堆 Issue/PR 不知道该先看哪个：真 Bug 还是误用？真需求还是
重复/刷量？这个 PR 真修好了吗？哪些可以放心让 AI 先修？

Fissue 把「**分诊 → 验证 → 修复**」自动化，并把每步的评分理由与证据留痕。核心主张——

> **别信模型的自述，要看独立证据。**

三条可执行原则：

1. 结论必须有**独立证据**：F2P（修复前失败、修复后通过）+ 仓库既有测试（回归门），而不是模型
   说「我修好了」。
2. 不可信的一切都在**沙盒**里跑：Issue 正文、外部 PR 代码、仓库自身代码、模型输出。
3. **永不自动合并**：AI 只提 PR / 打标签给建议，合并由人在平台上手动完成。

## 2. 核心流程

```
抓取（四平台，增量）→ 元数据预筛 + AI 分类 BUG / FEATURE
  ├─ Issue·BUG  : 评难度 → 写验证器 → 沙盒 base 验证 → verify 队列 → 批量定论
  │                → tier1/tier2 自动修复提 PR；其余打标签等开发者
  ├─ Issue·FEAT : 评可行性/难度/必要性 → 打标签
  └─ PR·BUG|FEAT: 判提交者 → 找关联 Issue → 写验证器 → 沙盒合并验证 → fix 队列
                  → 批量定论 → 打标签建议合并，由人手动合并
```

四条流水线互不干扰，详见[架构设计](Architecture.md)。

## 3. 交付形态

| 形态 | 入口 | 用途 |
|---|---|---|
| CLI | `fissue <命令>` | 单次 / 脚本化驱动全流程 |
| Web 工作台 | `fissue web` | 浏览器里看流水线（漏斗 / 看板 / 泳道）、条目、状态、仓库、设置 |
| REST API | 同 `fissue web`，`/api/v1` | 给脚本与 CI 用 |
| 常驻服务 | `fissue serve` | 增量扫描 + 队列调度 + 验证 + 阈值通知（`--with-web` 同进程带 Web） |

## 4. 技术栈

| 项 | 选型 |
|---|---|
| 语言 | Python 3.10+（CI：3.10 / 3.12 / 3.14 + windows-2022） |
| 交付 | CLI（typer）+ Web（FastAPI + Jinja2）+ REST API + 常驻服务 |
| 平台 | GitHub · Gitee · AtomGit · GitLab（含自建实例） |
| AI | 任意 OpenAI 兼容端点（DeepSeek / OpenAI / 通义 / Kimi / 本地 vLLM…） |
| 存储 | SQLite（默认，零依赖）· PostgreSQL / MySQL（可选，均已真机验证部署路径） |
| 沙盒 | Docker：禁网、非 root、只读根、限资源、只挂隔离工作区、可走受控转发通道 |
| 配置 | `.env`（密钥）+ `config.yaml`（业务规则）+ `config.local.yaml`（覆盖层） |

## 5. 它靠谱吗（摘要）

在**五套对抗性夹具（60 Issue + 20 PR）**上的真实测量，全文见[基准与可信度](Benchmark.md)。

**站得住**：

- 回归门在 3 套夹具上**全部拦下**「修好目标却弄坏别处」的假修复——F2P 单独做不到；
- 假修复、刷量、误报、设计偏好变更均被拦在自动修复之外；
- 重复检测能召回中文同义重复，且不误标「同源但非重复」；
- 真实提 PR 端到端跑通（`envkit#4` → PR #31、`lockkit#2` → PR #28），改动不含验证器测试文件；
- `pipekit` Issue 侧自动修复 **7/7**（2~3 轮内产出补丁）。

**公开保留**：

- **Gitee 条目级写**只剩「建/改 Issue」404（原因未定位）；打标签、评论、仓库级写都通。四平台
  **只读**链路全部跑通。
- tier 标定是**阈值边界抖动**而非稳定清单（评分密集在 62~82，门槛 80 正压右端）；功能后果为零
  ——两个 tier 都进修复队列，只差标签。

> 我们宁可把这些写出来，也不给一份「全部通过」的漂亮表格——那正是 Fissue 存在的意义所反对的事。
